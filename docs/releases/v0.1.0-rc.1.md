## What SCRAP is

SCRAP is an opinionated, durable, rebuildable single-node Kubernetes platform for self-hosting
applications: build the platform once, deploy applications into it through well-defined
integration patterns, and if the hardware dies, rebuild the platform and restore applications from
tested backups. See the repository root [`README.md`](../../README.md) and
[`docs/understanding-scrap.md`](../understanding-scrap.md) for the full picture.

## PROVEN NOW

Backed by a live, automated, CI-gated acceptance profile — not by prose alone. Full evidence
citations: `docs/release-readiness.md`'s own "PROVEN NOW" table.

- Core platform (CRDs, cert-manager + private CA, Gateway API ingress, local-path storage,
  observability core, backup engine) installs from zero and reconciles
- The one-directional dependency rule, and the two structural invariants T1 (deleting `apps/`
  leaves a complete platform) and T2 (adding an app touches only `apps/` plus one enabling file)
- All six application integration patterns (P1–P6), including a genuinely destructive restore of
  P5's stateful Redis example
- R1 (application-data loss) recovery, proven nightly against a real multi-tier application
  (Authentik + PostgreSQL), including quiescence ordering and stable-primary-key preservation
- Identity (Authentik), declaratively configured via Blueprints — P2 native OIDC and P3
  forward-auth, both positive and adversarial; CA-trust wiring; the recovery-flow-abuse invariant
  (no unauthenticated path to a password-set form), checked both structurally and behaviorally
- Grafana (real Prometheus query through it, real OIDC login, group→role mapping, anonymous access
  adversarially rejected) and Logs — Loki + Alloy (a real workload's stdout marker shipped, stored,
  and retrieved through Grafana's own configured datasource, with a passing negative control)
- Public TLS: issuer-independence, and a genuine ACME network round-trip (the `Order` stage)
  against Let's Encrypt's real servers, failing visibly on bad DNS-01 credentials
- Off-site (S3-compatible) backup — **artifact placement only**: a real remote write, an
  independent read using the intended recovery credentials, ADR-0010 host-isolation unaffected by
  destination, and a genuine, bounded, visible failure on bad credentials
- Alert delivery — a real `AlertmanagerConfig` webhook receiver genuinely delivers a live-fired
  alert to an ephemeral receiver, with a passing negative control
- Heartbeat — a real, conditional dead-man's-switch push, proven both healthy-pushes and
  unhealthy-withholds
- Dynamic DNS — a real RFC2136 `UPDATE` against an ephemeral authoritative nameserver, confirmed
  by an independent `dig` query, with a passing wrong-credential negative control and an
  unchanged-IP no-op path
- Public ingress — `verify-live.sh`'s certificate-identity oracle (SHA-256 fingerprint match)
  proven both green (real Gateway) and red (a deliberately different ephemeral endpoint)
- UPS — a real host-level NUT install genuinely runs `upsmon`'s `SHUTDOWNCMD` against a
  live-induced on-battery/low-battery state (with a passing negative control); the in-cluster
  exporter reads that same state through Prometheus and fails visibly on misconfiguration; kubelet
  Graceful Node Shutdown and a matching `systemd-logind` inhibitor are armed and verified live
- Topology B onboarding generator (`bootstrap/generate-topology-b.sh`) — a generated operator
  repository actually bootstraps and reconciles end to end, sourcing platform content from a
  separately, independently pinned `scrap-platform` source, with a passing negative control on the
  pin itself

## INTENDED FOR v1 BUT NOT YET PROVEN

Each item names a claim this candidate **does not make**. None of these are existence gaps in the
product surface — per ADR-0012, all six mandatory-before-`rc.1` surfaces (heartbeat, dyndns, UPS,
public ingress, alert delivery, Topology B generator) are implemented, above. What follows is
either qualification not yet run, or a permanent, by-design operator-run evidence boundary. None of
it blocks `v0.1.0-rc.1` from being cut — ADR-0011/0012 say so explicitly for each item below —
though most of it **does** block final v1.

| Gap | What's missing | Blocks `rc.1`? | Blocks final v1? |
|---|---|---|---|
| **R3 — host-loss recovery** | T-E (host-loss rehearsal), not yet implemented. Off-site backup proves one ingredient (artifacts reach independent storage), not the recipe. | No — ADR-0011 | Yes, mandatory |
| **R4 — site-loss recovery** | Depends on R3 above | No | Yes |
| **arm64 as a tested target** | T-D (arm64 minimal, nightly), not yet implemented. Accepted as a target architecture (`bootstrap/preflight/check-arch.sh` permits it); no CI run has exercised it. This is a qualification gap, not a product-surface gap — arm64 isn't one of ADR-0012's six pre-RC-mandatory surfaces. | No | Yes |
| **T-C (Connected, nightly)** | Heartbeat and alert delivery both exist and are proven at the level `t-a-alert-heartbeat.sh` establishes (see PROVEN NOW). T-C's remaining value is the *nightly* integration alongside real DNS-01 issuance — qualification infrastructure, not product surface; may land during the RC cycle. | No | No — infrastructure only |
| **T-F (upgrade testing)** | Cannot exist before a first release exists to upgrade *from*. `rc.1` is T-F's precondition, not something T-F blocks. | No — precondition, not a blocker | Yes, once a prior release exists |
| **Operator-run real-environment boundaries** | Real public certificate issuance against a real domain; real public reachability of a real install; a real UPS's behavior under an actual mains outage; a real third-party alert/heartbeat provider's own delivery/alarm acceptance. Each has a CI-provable oracle already proven (above); the real-world edge is a permanent, by-design operator-run boundary — not a temporary gap, never CI-executed. | No — by design | No — by design |

## DEFERRED / OPTIONAL / POST-v1

Not part of the v1 envelope at all. Full list and rationale: `docs/release-readiness.md`'s own
"DEFERRED / OPTIONAL / POST-v1" table.

- `scrap-patterns` companion repository of integration examples
- Talos as a host OS target
- Renovate / automated version-bump PRs
- A platform web UI
- Multi-node, HA, multi-cluster/fleet, distributed storage, multi-tenancy
- Dedicated R5 (account/credential loss) acceptance testing beyond the structural mitigation
  already proven (dual age recipients)

## CI evidence for the baseline this candidate builds on

The push-to-main suite for the accepted pre-PLAT-87 baseline (`b66af2b07987a2c728396233b7f71a6ce26d4317`)
completed 9/10 workflows green on first attempt; `T-A-offsite-backup` failed on its first attempt
during MinIO startup (`Server not initialized yet`). A rerun of that same workflow against the
identical commit passed end to end on its second attempt — confirmed directly against GitHub
Actions' own run history for that commit, not merely asserted. This is classified as a transient
MinIO readiness race, not a product regression; it's recorded here so any future exact-candidate CI
citation for this history stays honest rather than selectively quoted.

## Getting this release

`v0.1.0-rc.1` is tagged and published as a
[GitHub pre-release](https://github.com/platta/scrap/releases/tag/v0.1.0-rc.1). To install exactly
this candidate:

```sh
git clone https://github.com/platta/scrap.git
cd scrap
git checkout v0.1.0-rc.1
```

Then make your configuration choices and install — see
[Getting started](../getting-started.md) for the host prerequisites and the
`clusters/<your-instance-name>` step that belongs between the checkout and:

```sh
sudo CLUSTER_PATH=./clusters/<your-instance-name> sh bootstrap/install.sh
```

For a [Topology B](../decisions/0009-repository-topology.md) operator repository, pin the
`scrap-platform` source to the same tag instead of checking it out directly:

```yaml
ref:
  tag: v0.1.0-rc.1
```

Read the evidence boundary above before relying on this candidate — in particular, host-loss
recovery (R3/R4) is not proven, arm64 is an accepted but untested architecture, and no upgrade
path to or from any other release has been tested (T-F, above, has never run: `rc.1` is the first
release, so there is nothing yet to upgrade from).
